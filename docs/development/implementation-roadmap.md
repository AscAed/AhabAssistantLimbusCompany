# Implementation Roadmap

Status: implementation in progress as of 2026-11-13. The current authorized offline batches cover cooperative stop handling, configuration persistence and migration, three bounded Mirror screenshot-failure paths, resource sync, updater retry, and isolated build/archive checks. Stage 14 passed its Mirror regression, full suite, Ruff, and compile checks; Stage 15 rebuilt and verified an isolated package containing Stage 14 source. The current `.venv` passed an offline locked dry-run with no proposed changes. Mirror visual behavior, native package launch/exit, and release identity remain open. The checkpoint records exact evidence. The baseline is [the dated investigation](../audits/2026-11-12-documentation-baseline.md); decisions and alternatives are in [target architecture](../architecture/target-and-optimization.md). Each batch produces a reviewable diff and its own evidence. Prior results are not silently carried forward to a different revision.

## Execution Classes

- **Ready when evidence is supplied:** Mirror visual batches can start after sanitized representative full-frame fixtures are available. Keep team selection, EGO choice, shop fusion, routing, layouts and scroll behavior in separate reviewable batches.
- **Policy decision remains open:** the legacy meaning of `set_win_position: false` and Mirror behavior after team-code load failure are not established. Clarify each policy before changing its fallback behavior.
- **External evidence or conditions:** real-game and simulator behavior, native hit targeting, installed package identity, remote update behavior and release deployment require the relevant environment and separate authorization. Source inspection, a passing mock test or an archive hash does not close these gates.

Future implementation validation should follow [environment and validation](environment-and-validation.md): unique test temporary directories, offline fixtures, focused tests followed by proportionate broader checks, and a disposable build copy. CI uses Windows and Python 3.12, but configured CI is not evidence that a specific current run succeeded. Compare each milestone against the [reference reports](../INDEX.md) and record deviations, new decisions and residual risks in dated evidence.
