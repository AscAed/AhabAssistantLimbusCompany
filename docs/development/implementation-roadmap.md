## Execution Classes

- **First: current-worktree evidence.** The config-free source/test snapshot at `4fdb201faca9f08afac4c54196e75e9880b52500` passed 373 tests with 2 Windows symlink skips and Ruff. The hash-checked disposable build completed both PyInstaller targets, archive integrity, and 688 packaged-asset comparisons except the injected version stamp; it used the earlier `895c8bbe` snapshot, before PR #125, so it does not qualify this source tree. Exact artifact hashes and commands are in the [implementation handoff](../audits/2026-11-14-implementation-handoff.md). Keep tests/builds in fresh disposable copies with unique basetemp paths.
- **Independent policy batch.** The legacy `set_win_position` ambiguity is resolved for old boolean values: history shows the pre-preset UI exposed only its single `True` option, and the new `"free"` preset leaves the window position uncontrolled. Both old booleans now normalize to `"free"` only for pre-preset config versions; current string presets are preserved. The team-code failure fallback is documented in its original feature commit and has caller-level regression coverage; reconsider it only with evidence of a changed requirement.
- **Mirror sample batch.** Obtain approved, sanitized full frames with game version, resolution, scale, UI state and expected detections. Keep team selection, EGO choice, fusion, routing and scroll/layout in separate fixture-backed batches; without representative samples, visual qualification remains blocked.
- **Mirror failure-boundary batch.** `tasks/base/screenshot.py` now owns the shared bounded waiter used in Mirror, selected daily routines, and battle. Twelve previously unbounded screenshot-`None` loops in `Shop` use it; aggressive-fusion result handling applies its existing 15-attempt limit to every iteration, including no-match results. The remaining raw `None` check is inside a four-attempt scan. Mock regressions cover these error and no-match boundaries; the helper limits attempts, not wall-clock duration. Tests do not verify card recognition, target coordinates, or automatic recovery from already selected gifts.
- **Mirror orchestration capture batch.** Eight unbounded screenshot-failure continues in Mirror entry, the main loop, reward collection, starlight and initial-EGO selection, restart and event handling fail through the bounded waiter. Reward-card and theme-pack selection use it as well. Nine mock regressions cover these terminal paths. The observation selection scans have 12- and 5-iteration bounds; the search-road recovery loop checks its existing freeze/restart timeout before retrying capture. The suite for that batch passed 362 with 2 symlink skips; current full-suite status is summarized above. Visual and native-call limits remain open.
- **Mirror route-entry attempt batch.** `Mirror.road_to_mir()` now stops after at most 31 loop iterations, including recognized-action branches that previously continued without reducing the no-match counter. A regression reproduces repeated successful `drive` detections without any page transition and confirms the method invokes its existing return-to-menu recovery. This bounds control flow but does not prove the click or visual state changed on a live game.
- **Mirror reconnect retry-result batch.** `Mirror.run()` now immediately continues its main loop when `retry()` returns `False`, which signals that the game was restarted; this prevents dispatching state from the pre-restart capture. A regression verifies dispatch is skipped and a fresh screenshot cycle begins. The Mirror unit directory passed 55 tests and that batch's full suite passed 359 with 2 Windows symlink skips. This mock verifies orchestration only; no real reconnect or game state was exercised.
- **Aggressive-fusion missing-anchor batch.** `_processing_coordinates()` now returns no candidates when aggressive fusion has detected gifts but the first-row cutoff has not been initialized. Before the fix, the integrated normal-fusion path raised `TypeError` while comparing a gift y-coordinate with `None`; the new regression confirms the path completes without clicking candidate gifts. The Mirror unit directory passed 53 tests and that batch's full suite passed 360 with 2 Windows symlink skips. This verifies a control-flow and fail-closed boundary only; it does not validate the row anchor or any visual coordinate.
- **Second-system fusion configuration batch.** `TeamSetting.second_system_action` is declared `List[int]`, so Pydantic stores an enabled checkbox value as integer `1`; two fusion branches used identity comparison with `True` and therefore skipped the configured second-system mode. Both now use the field's truth value. Regressions verify the Level IV transition and that the second-system keyword is selected. The Mirror unit directory passed 55 tests and that batch's full suite passed 362 with 2 Windows symlink skips.
- **Initial EGO scroll batch.** `Mirror.select_init_ego_gift()` now caps the slash-gift scroll at 12 drags and raises `cannotOperateGameError` when the expected blunt-gift marker remains unavailable. One regression verifies exhaustion and that no initial gift-card click follows; another verifies the marker can succeed on the twelfth attempt and selection then proceeds. The Mirror unit directory passed 50 tests and that batch's full suite passed 357 with 2 Windows symlink skips. This verifies the control-flow boundary only; approved full-frame fixtures are still required to validate recognition and scroll behavior.
- **Observe EGO configuration bounds batch.** The GUI parser restricts systems, level/row/column ranges, and the total number of selections, but Mirror's runtime path previously trusted its `List[str]` config field. Regressions reproduced `IndexError` for an unknown system and four selection attempts from a four-item config. Runtime parsing now checks format, systems, levels 1–3, rows 1–10, columns 1–8, and the shared maximum of three valid selections before clicking; malformed values log and skip. The Mirror unit directory passed 57 tests and the current full suite passed 364 with 2 Windows symlink skips; Ruff passed. This validates input/control flow only. It does not verify visual gift detection or selection coordinates.
- **Update recovery batch.** Partial-copy, partial-file-delete and partial-directory-delete exception cases retry through fresh updater instances using persisted manifest and payload paths; tests check final files, cleanup and outside sentinels. Controlled subprocesses cover exit during full-update old-resource deletion and directory copy, after the first incremental file deletion, during partial directory deletion, after a partial replacement write, before syncing the temporary completion marker, after syncing it but before atomic rename, and during payload cleanup after the replacement has been applied. Separate tests cover process exit during `check_temp_dir_and_run()` self-staging, the distinct `_handoff_to_new_updater()` staged `copy2`, and Python safe-unpack extraction; bundled 7-Zip tests cover successful ZIP extraction and replay after an injected exit at the external-command boundary. The original updater overwrites and launches its complete staged copy on restart; a fresh extraction call overwrites the partial extracted file and adds missing files. A mocked process-enumeration regression now confirms unavailable names are skipped without affecting named-target termination. The marker lets a restarted updater skip reapplying completed files and retry cleanup; another regression confirms old cleanup preserves a newly downloaded archive. New regressions showed that `PermissionError` after partial deletion could be ignored and that nested `FileNotFoundError` could be mistaken for an absent old-resource root. Both now abort while the root remains; a genuinely absent root remains benign. A fresh updater instance reuses the retained payload after the obstruction is released and completes the update. The download path stages beside the destination, flushes and syncs the completed stream, then atomically replaces the final package; regressions preserve an existing package on interruption and check completion-signal order. Download failures now emit a user-facing signal and hide the progress ring; successful package and OCR downloads clear it. The earlier updater bounds file passed 42 with one Windows symlink skip, download tests passed 7, the three UI tests passed, and the earlier full suite passed 339 with 2 skips. The focused updater/download/UI group passed 54 with 1 symlink skip and full Ruff; the updater file passed 47 with one symlink skip, and the full suite at that checkpoint passed 358 with 2 skips. Ruff and compileall passed on that snapshot. This does not establish recovery from power loss, interruption during a live 7-Zip process, automatic rollback or installed-user-data recovery. Reopen this batch only for a concrete uncovered boundary or failure report.
- **Package and deployment batch.** The current Observe EGO configuration guards and shared three-item limit are included in a disposable build that passed archive integrity and all 688 asset-path comparisons; artifact SHA-256 values are in the implementation handoff. A read-only GitHub check on 2026-11-14 found no Actions runs, commit checks, or Releases for the fork; remote `main` matched local HEAD, with branch protection disabled. The deployment endpoint was unavailable, so external or manual deployment remains unknown. No package was launched. Next, use a separately authorized, isolated writable runtime/network environment for a startup/exit check, then qualify updater behavior and installed identity; real-game, simulator and remote release qualification remain separate gates.
- **Conditional architecture batch.** Only after measurement, compare an alternative capture backend, GPU inference or process isolation against the existing stack with correctness, latency, maintenance and packaging criteria.
- **External evidence or conditions:** real-game and simulator behavior, native hit targeting, installed package identity, remote update behavior and release deployment require the relevant environment and separate authorization. Source inspection, a passing mock test or an archive hash does not close these gates.
